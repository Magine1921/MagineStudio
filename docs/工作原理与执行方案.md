# MagineStudio 本地视频生成客户端：工作原理与执行方案

## 1. 项目目标

MagineStudio 是一个面向 Windows 10/11 普通用户的本地视频生成客户端。用户不需要理解 Python、CUDA、模型目录或 ComfyUI 节点，只需完成以下流程：

1. 打开客户端，自动检测电脑配置。
2. 查看“流畅运行、可以运行、实验性运行或不建议运行”的明确结论。
3. 选择 ComfyUI 安装位置、模型位置和视频输出位置。
4. 阅读并接受 MiniMax H3 社区许可及使用限制。
5. 点击一次开始安装；客户端自动下载、校验、解压、配置并支持中断后续传。
6. 在客户端内输入提示词或添加首帧图片，直接生成和预览本地视频。

首个可交付版本聚焦 NVIDIA 显卡与 Windows x64。AMD、Intel 和 macOS 后续通过独立运行时适配，不在首版中承诺一键可用。

## 2. 已核实的可行性与边界

### 2.1 官方状态

- MiniMax H3 已于 2026-07-31 发布并开放权重。
- ComfyUI 0.30.0 起原生支持 H3，官方提供 T2V、I2V 和 R2V 工作流。
- H3 Base 本地开源部分最高输出 768 像素短边、24 FPS，并原生生成双声道音频。
- 官方完整系统还包括 H3-Context-IR 和 H3-Regenerate-2K；这两部分目前不是本地开源模块。因此本客户端的“完全本地模式”以 H3 Base 768p 为边界，2K 只能作为显式的可选云服务功能，不能宣称完全本地。

### 2.2 最小模型组合

文生视频和首帧生视频共用 FL2VA 模型组合：

| 文件 | 作用 | 大小 |
|---|---|---:|
| `minimax_h3_fl2va_pruned_int8_convrot.safetensors` | 视频/音频扩散模型 | 19.53 GiB |
| `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors` | 文本与多模态编码器 | 14.61 GiB |
| `minimax_h3_video_vae_fp16.safetensors` | 视频 VAE | 4.85 GiB |
| `minimax_h3_audio_vae_fp32.safetensors` | 音频 VAE | 0.56 GiB |
| 合计 | T2V/I2V 最小模型包 | 39.55 GiB |

参考图/视频/音频生成还需 `minimax_h3_ref2va_pruned_int8_convrot.safetensors`，额外约 19.53 GiB。

考虑 ComfyUI、下载缓存、临时文件和输出空间，首版安装器采用以下磁盘门槛：

- T2V/I2V 基础包：至少 55 GiB 可用，建议 70 GiB。
- 加装 R2V：至少 80 GiB 可用，建议 100 GiB。
- 安装完成并校验成功后可删除约 2 GiB 的 ComfyUI 压缩缓存；模型下载的 `.part` 文件只有在对应文件校验成功后才会替换成正式文件。

### 2.3 许可边界

MiniMax H3 使用专门的社区许可，不是 Apache/MIT 通用开源许可。首版必须在下载模型前设置许可闸门：

- 用户必须打开或阅读官方许可，并主动勾选接受。
- 用户必须确认不在许可排除地区（欧盟、英国、韩国和美国）。
- 客户端保存许可版本和接受时间；许可版本变化后需重新确认。
- 客户端界面明确显示 `MiniMax H3`，并为生成内容提示 AI 标识义务。
- 客户端不内置或二次分发模型文件，而是从 Comfy-Org/MiniMax-H3 官方 Hugging Face 仓库直接下载。
- 首版提供本地使用安全提示和内容报告入口占位；正式商用发布前还需要法律审查、用户条款和内容安全策略。

## 3. 硬件扫描工作原理

### 3.1 采集项

客户端启动后在本机读取：

- Windows 版本、系统架构。
- CPU 名称、物理核心和逻辑线程数。
- 物理内存总量和当前可用量。
- NVIDIA GPU 名称、显存、驱动版本和 CUDA 计算能力。
- 所选安装盘/模型盘的可用空间。
- WebView2、Git、ComfyUI 现有安装和端口占用情况。

优先通过 `nvidia-smi` 获取精确 GPU 信息；若不可用，则使用 Windows CIM 查询并明确标记“无法确认 CUDA 可用”，不会把共享显存误认为独立显存。

### 3.2 分档规则

官方没有给出单卡消费级显卡的硬性最低配置，因此客户端使用“保守可更新规则”，而不是伪装成官方认证：

| 档位 | 基准条件 | 默认体验 |
|---|---|---|
| A 舒适 | NVIDIA CUDA、显存 ≥24 GiB、内存 ≥64 GiB | 768p、4–8 秒起步，可逐步提高时长 |
| B 可用 | NVIDIA CUDA、显存 16–23 GiB、内存 ≥32 GiB | 480p/544p、4–5 秒起步，使用模型卸载 |
| C 实验 | NVIDIA CUDA、显存 8–15 GiB、内存 ≥32 GiB | 352p/480p、4 秒，速度较慢且依赖虚拟内存 |
| D 高风险 | NVIDIA CUDA、显存 6–7 GiB、内存 ≥32 GiB | 仅低分辨率实验，可能极慢或内存不足 |
| 不支持一键 | 无 NVIDIA CUDA、显存 <6 GiB、内存 <16 GiB 或非 x64 Windows | 不开放默认本地安装按钮，提供说明 |

额外规则：

- 内存 16–31 GiB 会降低一档，并提示配置足够大的 Windows 页面文件。
- 模型盘空间不足时，即使 GPU 合格也不能开始安装。
- 驱动过旧时给出更新建议，不自动静默修改显卡驱动。
- 规则保存在版本化清单中，未来可更新；界面显示规则版本和“社区经验值，并非官方保证”。

## 4. 系统架构

```text
React 用户界面
  ├─ 首次设置 / 硬件报告
  ├─ 安装中心 / 下载进度 / 错误恢复
  ├─ 视频创作 / 参数预设 / 素材选择
  └─ 任务历史 / 视频预览 / 输出目录
          │ Tauri 安全命令边界
Rust 本地服务层
  ├─ HardwareScanner：系统、GPU、内存、磁盘扫描
  ├─ LicenseGate：许可版本与接受记录
  ├─ Installer：下载、续传、哈希校验、解压、配置
  ├─ RuntimeManager：启动、检测、停止 ComfyUI
  ├─ WorkflowBuilder：构建 T2V/I2V ComfyUI API 工作流
  └─ ComfyClient：上传素材、排队、轮询、取消和取回结果
          │ 仅绑定 127.0.0.1
ComfyUI 0.31.x 本地运行时
  ├─ H3 FL2VA / 可选 Ref2VA
  ├─ Qwen3-VL 32B H3 编码器
  ├─ 视频 VAE + 音频 VAE
  └─ MP4 输出目录
```

选择 Tauri 而不是 Electron，原因是安装包更小、Rust 更适合系统扫描和长文件下载，并且前端与本地文件/进程之间有明确的命令白名单。

## 5. 一键安装流程

### 5.1 安装前检查

1. 校验许可已经接受且版本匹配。
2. 路径必须是绝对路径，不能是磁盘根目录或 Windows 系统目录。
3. 检查目标盘剩余空间和写入权限。
4. 检查是否已有安装任务运行，避免重复并发写入。
5. 生成安装计划，向用户明确将下载哪些文件、总大小和目标位置。

### 5.2 下载与恢复

- ComfyUI 使用固定版本的官方 Windows NVIDIA Portable 包，首版固定为 v0.31.0 CUDA 12.6 兼容包。
- 模型从官方 Comfy-Org/MiniMax-H3 下载。
- 所有大文件先写入 `.part`，使用 HTTP Range 续传。
- 每个模型按 Hugging Face LFS SHA-256 校验；ComfyUI 安装包按 GitHub Release 提供的 SHA-256 校验。
- 校验失败保留错误信息并允许重新下载，不把损坏文件改名为正式文件。
- 下载进度事件包含当前阶段、单文件进度、总进度、已下载字节和可恢复的错误建议。

### 5.3 解压与配置

1. 在目标目录内解压 ComfyUI Portable。
2. 保留用户单独选择的模型目录，不强制复制到 ComfyUI 安装目录。
3. 自动生成 `extra_model_paths.yaml`，把 `diffusion_models`、`text_encoders` 和 `vae` 映射到模型目录。
4. 写入 MagineStudio 安装标记，记录版本、模型文件和哈希。
5. 启动 ComfyUI，访问本地健康检查接口。
6. 健康检查通过后把状态标记为“可生成”；失败则显示日志摘要和修复动作。

### 5.4 安全设计

- 下载域名和文件名使用应用内白名单，远程响应不能直接变成可执行命令。
- 调用系统程序时使用参数数组，不拼接 shell 命令。
- ComfyUI 默认只监听 `127.0.0.1`，不暴露到局域网。
- 路径写入前进行清理和范围校验，不对磁盘根目录执行递归删除或覆盖。
- 首版不会自动安装来源不明的自定义节点。
- 日志默认隐藏提示词和素材内容，只记录技术错误。

## 6. 本地视频生成流程

### 6.1 T2V 文生视频

1. 用户输入中文或英文提示词，选择画幅、清晰度预设、时长和随机种子。
2. 客户端将时长转换为 H3 所需的 `17k+5` 帧网格，帧率固定为 24 FPS。
3. 客户端构建只含官方原生节点的 ComfyUI API 工作流。
4. 提交到 `http://127.0.0.1:8188/prompt`。
5. 轮询任务状态，完成后从 ComfyUI `/view` 接口加载 MP4。

### 6.2 I2V 首帧生视频

1. 用户选择首帧图片。
2. 客户端先上传到 ComfyUI 本地输入目录。
3. 工作流增加 `LoadImage`，并连接到 `MiniMaxH3ImageToVideo.first_frame`。
4. 其余采样、视频 VAE、音频 VAE 和保存流程与 T2V 相同。

### 6.3 默认参数

| 硬件档位 | 预览分辨率（16:9） | 默认时长 | 采样步数 |
|---|---:|---:|---:|
| A | 1344×768 | 5 秒 | 20 |
| B | 960×544 | 5 秒 | 20 |
| C | 864×480 | 4 秒 | 16 |
| D | 608×352 | 4 秒 | 12 |

用户可以调整，但超出档位建议时必须看到显存/时间风险提示。

## 7. 界面与交互方案

应用采用深色创作工具风格，但不使用低对比度“纯黑加霓虹”堆叠。核心页面：

1. **设备**：一眼看到结论、设备明细、限制原因和建议预设。
2. **安装**：分步显示路径、许可、组件选择、磁盘占用和安装进度；每屏只有一个主要按钮。
3. **创作**：提示词为视觉中心，高级参数渐进展开；生成期间按钮禁用并提供取消。
4. **作品**：视频预览、状态、错误恢复、打开输出目录。

可访问性要求：

- 所有字段有可见标签；所有图标按钮有文字或 `aria-label`。
- 键盘可完成全部流程，焦点环清晰。
- 状态不只依赖颜色，同时使用文字和图标。
- 支持 `prefers-reduced-motion`，动画只用于状态转换且不超过 300 ms。
- 错误信息说明原因和下一步，不只显示“失败”。

## 8. 执行阶段

### 阶段 1：可运行 MVP（本次执行）

- 初始化 Tauri + React + TypeScript 项目。
- 实现 Windows/NVIDIA 硬件扫描与分档。
- 实现设置持久化、三个自定义目录和磁盘检查。
- 实现 MiniMax H3 许可确认。
- 实现 ComfyUI 与基础模型的断点续传、SHA-256 校验、解压和路径配置。
- 实现 ComfyUI 启停与健康检查。
- 实现 T2V 和可选首帧 I2V 工作流提交、状态轮询、取消和视频预览。
- 完成前端界面、单元测试、生产构建和 Windows EXE/MSI/NSIS 打包。

### 阶段 2：产品化增强

- 动态签名的远程模型清单和安装器自更新。
- R2V 多参考素材编辑器。
- 下载镜像选择、限速、代理与断点管理。
- 任务历史数据库、缩略图和参数复用。
- 崩溃日志脱敏、自动诊断包和修复向导。
- 安装包代码签名、自动更新签名和发布流水线。

### 阶段 3：多硬件与商用

- AMD ROCm/ZLUDA、Intel、国产芯片和 Linux 运行时适配。
- 可选 H3-Context-IR / 2K Regenerate 云服务连接。
- 商用许可评估、用户条款、内容安全策略、举报与审计机制。
- 自动基准测试形成更可靠的机型数据库。

## 9. 本次验收标准

1. 在 Windows x64 上能生成可安装的 EXE。
2. 启动后无需管理员权限即可完成硬件扫描。
3. 扫描结果包含 GPU、显存、内存、磁盘、档位、原因和推荐参数。
4. 用户可分别选择 ComfyUI、模型和输出路径，设置重启后保留。
5. 未接受许可或空间不足时无法开始模型下载，并显示明确原因。
6. 安装计划能精确显示约 41.5 GiB 基础下载量，安装支持中断续传和哈希校验。
7. 能启动只监听本机的 ComfyUI，并检测是否就绪。
8. 能提交 T2V；选择首帧后能提交 I2V；能取消任务并预览生成 MP4。
9. 前端构建、Rust 测试和 Tauri 生产打包均通过。
